# What is a REST API?

> Facts used: REST stands for Representational State Transfer. Roy Fielding defined it in chapter 5 of his 2000 PhD dissertation at UC Irvine ("Architectural Styles and the Design of Network-based Software Architectures"). In a REST API each resource has its own URL; clients use HTTP methods (GET to read, POST to create, PUT to replace or update, DELETE to remove); the server answers with a status code (200 OK, 404 Not Found) and the data; REST is stateless, so every request carries all the information the server needs, which is what lets a server handle many clients. Sources: ics.uci.edu/~fielding/pubs/dissertation/ (chapter 5), the HTTP specification for methods and status codes.
